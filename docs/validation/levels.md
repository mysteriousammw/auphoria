# Maturity levels

AUPHORIA ships analyses with an explicit maturity tier. The tier is recorded
in each analysis's `manifest.yaml` under `maturity`, and the validation
dashboard (`dashboard.md`, generated by
`scripts/gen_validation_dashboard.py`) reports it per analysis.

| Tier | Meaning | Who may set it | Requirements |
|------|---------|----------------|--------------|
| `experimental` | Ships, has basic tests, but not yet cross-checked against an independent reference. Use for exploration only. | build agent | Automated tests exist. |
| `tested` | Automated tests pass with **known answers** — small synthetic data whose expected values are hand-computed and/or taken from a documented reference example, matched against SciPy/statsmodels/scikit-learn. | build agent | Known-answer tests; reference values recorded in `references/`. |
| `reviewed` | An independent, named **human** statistician reviewed the analysis and its reference cross-check, and signed off. | human reviewer only | `reviewer` field set in the manifest; `reference` describing the cross-check. Enforced — a `reviewed` manifest without a reviewer **fails validation**. |
| `validated` | Reproduced against an independent implementation (e.g. R `stats`, a published worked example, or a second-language port) with exact values and a named human reviewer's sign-off. | human reviewer only | `reviewer` + `reference` set; independent reproduction on file in `references/`. Enforced like `reviewed`. |

## Enforcement

The build agent (this tool) may only ever set `experimental` or `tested`.
`reviewed` and `validated` require a named human reviewer in the manifest's
`reviewer` field, and a `reference` describing what was cross-checked against.

A manifest claiming `reviewed` or `validated` without both `reviewer` and
`reference` is rejected:

- at **load time** (`registry.discover()`, via `core/manifest.py::validate_maturity`);
- by the **dashboard generator**, which fails the regeneration;
- by a **test** that tries to validate such a manifest.

See `docs/validation/` — `references/` for the recorded reference values and
`KNOWN_ISSUES.md` for outstanding known problems.
