# Design decisions (AUPHORIA)

This file records every non-obvious decision made while building AUPHORIA,
with one line of reasoning each. New decisions are appended; nothing is
rewritten after the fact (a dated entry is added instead).

## Publish preparation (2026-10-29)

### Clean publish copy
- **Decision:** `scripts/prepare_publish.py` builds a fresh `../auphoria_publish/`
  by COPYING only the whitelisted root entries (`pyproject.toml`, README,
  PROGRESS, CHANGELOG, CITATION, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY,
  CONTRIBUTORS, .gitignore, LICENSE(if present), src, notebooks, catalog,
  docs, tests, scripts, .github) and excluding results/venv/caches/build/
  dotfiles/>5MB. It never modifies the original tree.
  *Reasoning:* a disposable, audited copy is the safe way to review exactly
  what will be public without risking the working tree.
- **Decision:** `docs_site/`, `mkdocs.yml` and root `conftest.py` are ALSO
  copied even though the literal publish list omits them.
  *Reasoning:* the docs site is the public documentation and `mkdocs.yml` +
  the root `conftest.py` fixture are required for the tests/docs to run from
  the published repo, so they belong in the repository.
- **Decision:** `site/` (mkdocs build output) and `*.log` are added to
  `.gitignore` and excluded from the copy.
  *Reasoning:* generated output, and the mkdocs test writes a `.log`.

### Credits in CITATION.cff
- **Decision:** `CITATION.cff` lists people only (no AI tools as authors);
  Abdul Momin Muhammad Wisal is the sole active author and the other four
  people stay in a commented block until each `[CONFIRM ROLE]` is replaced.
  *Reasoning:* the task requires AI tools never to appear as authors, and the
  other four people may only be added after their roles are confirmed.
- **Decision:** the only email allowed anywhere is `ammw@aup.edu.pk` (approved
  for README + CITATION.cff); the privacy scan treats any other address as a
  WARNING.
  *Reasoning:* the task approved exactly one project-contact address.

### Publish report + install test
- **Decision:** the report is generated by the same script that makes the copy,
  and the script also runs a fresh-venv `pip install .` /
  `auphoria --version` / `doctor` / `demo` / `pytest` and records each result as
  PASS/FAIL rather than assuming.
  *Reasoning:* the acceptance is evidence, not assertion; a command only counts
  as passed if the script ran it and saw exit 0.
- **Decision:** `"auphoria.analyses" = ["*/manifest.yaml"]` was added to
  `pyproject.toml` package-data — the fresh-venv `auphoria demo` failed with
  "Analysis directory 'ancova' has no manifest.yaml" on a real (non-editable)
  install because the analysis manifests were never shipped in the wheel. The
  editable dev venv reads the source tree so it hid the gap (same class of bug
  as the report template/advisor rules): verified by `pip wheel` (19 manifests
  now ship) and by the fresh-venv demo.
  *Reasoning:* packaging bugs that only appear on a real install are exactly
  what the publish audit exists to catch.
- **Decision:** the fresh-venv pytest step installs `.[dev]` (not just pytest)
  so the full suite can collect — a bare core install cannot import the
  discipline-pack-dependent per-analysis tests, which would report 9 fake
  collection errors.
  *Reasoning:* the full suite is a dev/contributor target; the core install is
  what `auphoria demo` proves end to end.

- **Decision:** `CONTRIBUTORS.md` uses a short "Who we are" paragraph plus a
  Name / Position / Research focus / Role in AUPHORIA / Contribution areas
  table, built ONLY from the confirmed facts (the Refined Part 2 spec). Research
  foci and positions are taken verbatim from the profiles given (Assistant /
  Associate Professor, "MPhil researcher"/"research student", and the two PhD
  universities named); no other institution, degree programme, or title is
  invented, and nobody is called an "MPhil supervisor".
  *Reasoning:* the task forbids adding any detail beyond what was written and
  forbids a university/degree mention except those stated.
- **Decision:** `docs/ACKNOWLEDGEMENTS.md` names no university or institution —
  it has a `[CONFIRM]` funding/institutional placeholder and the open-source
  library list with permissive licences read from `pyproject.toml`.
  *Reasoning:* no institution may be named by default.

## Phase 11 (2026-10-29)

### Docs site
- **Decision:** the docs site lives in `docs_site/` (not the root `docs/`) with
  `docs_dir: docs_site` in mkdocs.yml.
  *Reasoning:* the root `docs/` holds the project's own development records
  (DECISIONS, validation, research); keeping them separate from the user-facing
  site avoids nav collisions and lets the site build cleanly.
- **Decision:** per-analysis pages are GENERATED from the manifests by
  `scripts/gen_analysis_docs.py`, not hand-authored.
  *Reasoning:* the analysis pages must never drift from the actual manifests;
  regeneration + a "--check is current" test keep them in lockstep (same
  philosophy as the validation dashboard).
- **Decision:** the shared validation / discipline-pack / decision-guide /
  known-issues content lives in `docs/` and is pulled into the site at build
  time with the `mkdocs-include-markdown` plugin (`{% include ... %}`).
  *Reasoning:* one source of truth; the site can't show a stale copy. The
  include path is RELATIVE TO THE INCLUDING FILE (`../../docs/...` from
  `docs_site/research/`), so a wrapper page in a subdirectory needs the extra
  `../`.
- **Decision:** install command blocks use `REPO_URL_PLACEHOLDER` and are
  marked TODO-VERIFY until the repository is published; `site_url`/`repo_url`
  use `https://github.com/REPO_URL_PLACEHOLDER` because mkdocs rejects a
  scheme-less URL, and set_repo_url.py substitutes the real address later.
  *Reasoning:* the build must pass before upload; the placeholder keeps every
  published reference in one literal set_repo_url.py can replace.
- **Decision:** the acceptance criterion is encoded in `scripts/build_docs.sh`
  and a pytest (run `mkdocs build`, assert zero WARNING/ERROR lines, exit 0),
  with the vendor Material EOL banner silenced via `NO_MKDOCS_2_WARNING=1`.
  *Reasoning:* a warning-free build is the stated acceptance; encoding it makes
  it checkable, not anecdotal.

## Phase 10 (2026-10-29)

### Validation framework
- **Decision:** maturity is a closed 4-tier enum — `experimental`, `tested`,
  `reviewed`, `validated`. The build agent may set only the first two;
  `reviewed`/`validated` require a named human reviewer in the manifest's
  `reviewer` field and a `reference` describing the cross-check.
  *Reasoning:* the engineer who wrote the analysis cannot unilaterally call it
  reviewed or validated — that is a human statistician's judgement — so the
  tool enforces the boundary mechanically rather than trusting convention.
- **Decision:** the reviewer gate is enforced in THREE places: pydantic
  (`maturity` enum), `registry` load (`validate_maturity`), and the dashboard
  generator (fails the regen). Maturity is validated in `core/manifest.py`,
  not ad-hoc in the registry.
  *Reasoning:* one definition, three call sites, so an analysis cannot slip a
  bogus tier past discovery or past a stale dashboard.
- **Decision:** independent references are stored as machine-readable fixtures
  (`docs/validation/references.yaml`: `source`, `how_produced`, `values` with
  tolerances) rather than prose, and the dashboard is generated from the
  manifests + fixtures by `scripts/gen_validation_dashboard.py`.
  *Reasoning:* a regenerated dashboard cannot drift from the actual manifests;
  R is not a runtime dependency, so the reference is a hand-computed textbook
  example and/or second-library reproduction (scikit-learn / statsmodels /
  SciPy), recorded explicitly per analysis.
- **Decision:** a `docs/validation/KNOWN_ISSUES.md` file (grouped per
  analysis) and a `.github/ISSUE_TEMPLATE/wrong_result.md` template whose
  acceptance is a recorded, passing independent cross-check.
  *Reasoning:* known limitations are part of honest validation, and the issue
  template makes "matches an independent reference" the definition of a fix.

## Phase 9 (2026-10-29)

### Discipline packs (optional installs)
- **Decision:** each discipline pack is a pyproject "extra" so `pip install
  auphoria` stays light; heavy deps (statsmodels, scikit-learn, PyDESeq2,
  gseapy) live only inside their packs' extras.
  *Reasoning:* a student installs only the packs they use; the core statistical
  stack stays small and fast.
- **Decision:** analyses declare `pack` (list) + `requires` (heavy module
  names) in their manifest, and the engine refuses to run an analysis whose
  `requires` are not importable, printing the exact pack install command
  (`pip install "auphoria[<pack>] @ git+REPO_URL_PLACEHOLDER"`).
  *Reasoning:* without the guard a missing heavy dep would surface as a raw
  ImportError after work begins; the guard teaches the fix and fails fast,
  before the module even loads.
- **Decision:** `pack` is a list, not a single string, because a discipline
  analysis belongs to several packs (e.g. ancova = agri-animal/health/social).
- **Decision:** pack metadata lives in `packs/packs.yaml` (canonical registry
  shipped in the wheel) while each analysis's manifest records its own
  membership; `catalog/analyses.yaml`'s `pack` field keeps the roadmap.
  *Reasoning:* the pack manifest is machine-checkable at runtime, the per-
  analysis fields live next to the code they describe, and the human catalogue
  documents the plan.

## Phase 8 (2026-10-29)

### Advanced analyses + expert-review notice
- **Decision:** advanced analyses carry a prominent "needs expert review"
  notice when used outside intended conditions. Implemented as
  `AnalysisResult.expert_review` (list) + `add_expert_review()`, threaded by the
  engine into run.json and rendered as a banner in report.html.
  *Reasoning:* advanced statistics are easy to misuse; when the data are small,
  assumptions violated, or results fragile, the student must be told to get a
  statistician's judgement — not left to over-read the numbers.
- **Decision:** advanced analyses state assumptions and minimum sample sizes
  especially clearly (in the manifest and as WARN verdicts / expert-review
  flags), and refuse (AssumptionError, not silent) when a design prerequisite
  is missing (e.g. mixed-effects needs a cluster with >1 obs).
- **Decision:** build the batch by delegating each analysis to a parallel
  subagent (self-contained brief with hand-computed/reference test values), then
  verify EVERY analysis by running its demo against a real sample file — not
  just its unit tests, which call `run()` and can miss `check_fit()` bugs.
  *Reasoning:* unit tests that bypass the engine miss engine-path failures
  (four were caught this way: ml-regression UnboundLocalError, over-strict
  label/reference guards, a demo input-name mismatch).
- **Decision:** `diagnostic-test` and `ml-classification-eval` accept a numeric
  binary 0/1 column as reference/label (not only categorical), with the
  2-class check done in `run()`.
  *Reasoning:* 0/1-encoded classes are common in spreadsheets; refusing them
  would be unhelpful, while insisting the check happen at run time keeps the
  guarantee that two classes genuinely exist.
- **Decision:** use a new deterministic sample dataset per analysis family
  (growth_cov, schools, psych, survival, diagnosis, features) rather than
  overloading the existing ones.
  *Reasoning:* each advanced analysis needs data shaped exactly for its design
  (nested units for mixed-effects, time+event+group for survival, etc.); the
  Phase-6 samples cannot serve all of them.

### Fixes
- Registry discovery now skips `__pycache__`; a cached bytecode dir was being
  treated as an analysis and broke discovery.

## Phase 7 (2026-10-29)

### Advisor architecture
- **Decision:** the advisor's decision logic lives in `advisor/rules.yaml`
  (a readable encoding of `docs/research/decision-guide.md`), evaluated by
  `advisor/advisor_engine.py`; no analysis-matching logic is hard-coded in
  Python.
  *Reasoning:* a statistician can read and edit the rules without touching
  code, and the YAML is the single source of truth for "which analysis fits
  which data + question" (mirrors the one-source-of-truth rule for
  `core/fitting.py`).
- **Decision:** the advisor recommends only analyses actually present in the
  registry (built); planned-but-unbuilt analyses (regression, survival,
  Cronbach, PCA, ML) never appear as recommendations.
  *Reasoning:* recommending an analysis the user cannot run would be worse
  than silence; the advisor test asserts every built analysis is covered by a
  rule, which nudge-adds a rule when a new analysis is built.
- **Decision:** group/id detection honours wizard-confirmed column roles and
  falls back to data shape (all-unique subject column = id; the most-
  categorical column = group).
  *Reasoning:* the student already told us the roles in the wizard, so the
  advisor should trust that over guessing; the shape fallback keeps
  `auphoria suggest --data FILE` (no roles) useful.
- **Decision:** `auphoria suggest` with no `--question` aggregates every
  question's advice (deduped, best reason first); `--question/-q <id>` narrows
  to one question.
  *Reasoning:* the CLI is script-safe (no interactive prompt when stdin is
  piped), so it cannot ask the question the wizard does; showing everything the
  data supports is the useful default, and the flag gives focus.
- **Decision:** `rules.yaml` is registered in `[tool.setuptools.package-data]`
  and `src/auphoria/advisor` added to pytest `testpaths`.
  *Reasoning:* without package-data the wheel would ship without the advisor's
  decision logic (the same trap as the report template); without the testpaths
  entry the 42 advisor tests were silently skipped by plain `pytest`.

## Phase 1 (2026-10-24)

### Language and dependencies
- **Decision:** Python 3.10-3.12 only; depend only on NumPy, pandas, SciPy,
  Matplotlib, PyYAML (plus optional `openpyxl` for Excel).
  *Reasoning:* these are preinstalled on Google Colab's default runtime, so
  installing AUPHORIA there does not disturb the environment.

- **Decision:** Use `argparse` from the standard library for the CLI rather
  than `click`/`typer`.
  *Reasoning:* one fewer dependency; argparse is sufficient for a thin
  front end.

- **Decision:** Matplotlib is forced to the `Agg` backend for all figure
  rendering (no display needed).
  *Reasoning:* AUPHORIA is headless; this guarantees figures render on
  servers and CI without an X server.

### Architecture
- **Decision:** One engine, thin front ends. All analysis logic lives in
  `auphoria.run(...)` or in analysis modules; the CLI and the Colab notebook
  only collect inputs and call the engine.
  *Reasoning:* a single, testable path so CLI, notebook and future front
  ends cannot drift.

- **Decision:** The analysis registry reads each analysis's `manifest.yaml`
  from the installed package; `catalog/analyses.yaml` is the human-facing
  catalogue and is kept in sync by a test.
  *Reasoning:* manifests must always be present at runtime (they are shipped
  in the wheel); the catalogue is documentation.

- **Decision:** The `id` in each manifest must equal the analysis module
  directory name; ids are the public stable identifiers.
  *Reasoning:* one canonical name to avoid "export" vs "export2" mismatches.

### Data integrity (guardrails)
- **Decision:** Never silently drop, change, or impute data. Missing values
  are always counted and reported; a test refuses to run when it would be
  meaningless (e.g., t-test with more than two groups).
  *Reasoning:* the highest-value behaviour for this audience is honesty;
  quiet data mangling is the failure mode that invalidates student work.

- **Decision:** Column typing is inferred (numeric / categorical / datetime /
  text) but the student confirms it in the interactive flow; a non-numeric
  column used in a numeric role causes a refusal with a plain-English fix.
  *Reasoning:* beginners cannot be silent-victims of a mis-parsed column.

- **Decision:** When a numeric requirement cannot be met by a column, the
  analysis errors with the offending values shown, rather than coercing.
  *Reasoning:* coercion would silently change data, which is forbidden.

### Statistics choices
- **Decision:** The independent-samples t-test defaults to the **Welch**
  variant (unequal variances) rather than Student's pooled test.
  *Reasoning:* Welch is robust when variances differ and is the modern
  default recommendation; it is exposed as the `equal_var` parameter.

- **Decision:** Pearson correlation reports `r`, two-sided `p`, and `n`, and
  omits a regression line unless clearly labelled as a visual trend aid.
  *Reasoning:* avoids implying a causal fit from correlation.

### Output & reproducibility
- **Decision:** Default results root is `~/AUPHORIA_results/...` via
  `Path.home()`, which resolves to the user's home on all platforms.
  *Reasoning:* students never know where their data went otherwise.

- **Decision:** `report.html` is fully self-contained (inline CSS, base64
  figures).
  *Reasoning:* a single file can be opened, screenshotted, and shared
  without a web server or package install.

- **Decision:** `replay.sh` and `replay.ps1` re-invoke the same
  `auphoria run` command with every resolved parameter and the seed; they do
  not embed data.
  *Reasoning:* replay must work on the same machine minus nothing, and must
  not encourage distributing raw data.

- **Decision:** Random seed defaults to a fixed constant (`1`) and is always
  recorded in `run.json`.
  *Reasoning:* fixed seed = reproducible figures/any randomisation; recording
  it makes every run self-documenting.

### Error handling
- **Decision:** Errors thrown to the user are plain English with a suggested
  fix; full tracebacks go only to `log.txt`.
  *Reasoning:* beginners cannot read tracebacks, but developers need them.

### Scope
- **Decision:** Excel `.xls` (legacy binary format) is not supported; the
  adapter tells the user to convert to `.xlsx` or CSV.
  *Reasoning:* `.xls` needs the unmaintained `xlrd`; `.xlsx` via `openpyxl`
  covers the realistic case.

- **Decision:** Phase 1 ships exactly three analyses (summary, t-test,
  correlation) to prove the engine; more follow in later phases.
  *Reasoning:* breadth before correctness would undermine trust in the engine.

- **Decision:** Only two run locations: the student's computer and Google
  Colab. No server, HPC, cloud-hosting or web-app features.
  *Reasoning:* keeps scope tight and the privacy story simple.

### Late decisions (still phase 1)
- **Decision:** The `dev` extras include `openpyxl` so the test suite
  (`tests/test_adapters.py::test_xlsx_reads...`) is self-contained in a clean
  install.
  *Reasoning:* a repeatable, off-the-shelf dev install should exercise the
  Excel path without an extra manual step.

- **Decision:** In the descriptive summary, `n` is the number of *non-missing*
  values used and `missing` is reported separately in the same row; stats are
  computed on non-missing values only.
  *Reasoning:* a student sees both counts side by side, and nothing is imputed
  or silently dropped — the two numbers tell the honest story.

- **Decision:** Duplicate/blank column names in a data file are made unique by
  the adapter's reader (pandas renames to `a`, `a.1`, `a.2`); the returned
  frame always has unique columns so menus never address the wrong one.
  *Reasoning:* uniqueness is a hard precondition for safe column mapping, and
  exact source headers are preserved in the preview/warnings.

## Phase 0 research decisions (2026-10-24)

- **Decision:** Treat the catalogue as the *plan* and each manifest.yaml as the
  *reality*; a test asserts built analyses ⊆ catalogue, not equality.
  *Reasoning:* the research catalogue lists 31 planned analyses across packs
  but only a few are built yet; equating the two would block expanding the
  roadmap before the code catches up.

- **Decision:** P1 (ship-first) = 18 analyses, one per the landscape evidence,
  ≤ 30 cap, covering every discipline.
  *Reasoning:* descriptive stats + bivariate tests + simple/multiple regression
  (the universal core), non-parametrics (normality-failure branch), and the
  health / econ / psychometrics / ML specialisations that appear at MS+.

- **Decision:** pingouin is GPL-3.0; **do not make it a required dependency**.
  Implement effect sizes / t-tests / reliability with scipy + statsmodels +
  numpy/ sklearn, which are all permissive (BSD/MIT).
  *Reasoning:* AUPHORIA is MIT; a GPL core dependency creates a licensing
  conflict for a general-purpose tool.

- **Decision:** prefer statsmodels (and lifelines only sparingly) for
  regression/ANOVA/survival rather than pingouin or autograd-dependent libs.
  *Reasoning:* keeps the dependency set permissive and smaller; verified to
  resolve on Python 3.10 (library-check.md).

- **Decision:** Word (.docx) and PDF are NOT supported data sources in v1.
  *Reasoning:* they are documents, not reliable tabular data; parsing them
  would add fragile heavy deps and risk silent data corruption. Give the
  student a copy-paste-to-.xlsx/.csv path instead (file-formats.md).

- **Decision:** support reading .sav (SPSS) and .dta (Stata) via optional
  extras, but recommend CSV as the default.
  *Reasoning:* psych/social theses arrive in SPSS/Stata; supporting them avoids
  stranded students, while CSV stays the no-dependency reliable path.

- **Decision:** the advisor will be driven by the plain-language decision
  guide (docs/research/decision-guide.md) — question type → variable types →
  groups → design → sample size.
  *Reasoning:* matched menu expectations from jamovi/JASP/SPSS and the
  evidence in the landscape doc.

## Phase — CLI skeleton & packaging decisions (2026-10-24)

- **Decision:** Build backend is `setuptools.build_meta` (setuptools + the
  pyproject.toml path).
  *Reasoning:* zero extra tooling (no hatchling/poetry), a src/ layout + a
  single console script are all `core` needs, and setuptools is preinstalled on
  Colab and every target Python — the least-risk choice across 3.10-3.12 and
  Colab.

- **Decision:** CLI uses Typer (not argparse anymore).
  *Reasoning:* the completion/help UX is friendlier for beginners, Typer is
  MIT and resolves on Python 3.10-3.12. The CLI stays a thin front end — it
  still only calls `auphoria.run(...)`.

- **Decision:** CLI errors are surfaced as return codes (`typer.Exit` /
  `standalone_mode=False`), never as tracebacks on screen.
  *Reasoning:* matches the "errors are plain English, tracebacks only to the
  log" rule.

- **Decision:** `doctor` checks Python version in range, imports the required
  libraries, and probes the results folder for writability; exits nonzero on
  any failure.
  *Reasoning:* gives a student one command that confirms AUPHORIA can run on
  their machine before they bring their data.

- **Decision:** `scripts/set_repo_url.py` refuses any address that is not a
  GitHub repository URL.
  *Reasoning:* the spec-updated requirement guards against a typo silently
  misrouting the README's `pipx` / `uvx` install commands.

- **Decision:** No `LICENSE` file and no `license`/`License ::` metadata until
  the maintainer chooses (docs/LICENCE_DECISION.md documents the options).
  *Reasoning:* packaging/licensing is the maintainer's call; shipping a default
  (e.g. MIT) would decide it for them.

- **Decision:** CI runs ruff (lint) plus tests on Python 3.10/3.11/3.12 across
  ubuntu, windows and macos.
  *Reasoning:* AUPHORIA must work cross-platform for its student audience;
  running per-Python-per-OS is the honest check even if it only activates after
  upload.

## Phase 2 — Core engine decisions (2026-10-24)

- **Decision:** Manifests are validated with pydantic (`core/manifest.py`), and
  the registry uses that validator.
  *Reasoning:* a malformed manifest should fail with a plain-English message
  naming the offending field, not a mystifying downstream exception; pydantic
  gives schema validation with readable errors for free.

- **Decision:** The rich "data card" is a separate module (`core/data_card.py`)
  layered on top of the existing simple advisor — the advisor still drives the
  menu's "which analyses fit", the data card injects a slower-but-richer
  per-column and value-level audit.
  *Reasoning:* keeps the fast menu path fast while giving `describe` and the
  pre-run audit the depth the spec wants.

- **Decision:** Outliers (IQR rule) and suspicious values (negative age,
  percentage out of range) are FLAGGED ONLY — never removed, never imputed,
  never changed.
  *Reasoning:* a flag invites inspection; silent deletion would corrupt the
  student's analysis and betray the project's core promise.

- **Decision:** Column kinds include ordinal, binary, id and free_text on top
  of numeric / categorical / date, and each column gets a suggested role
  (outcome / group / covariate / id / time / weight) the user confirms.
  *Reasoning:* job-relevant typing improves both the menu offers and the report.

- **Decision:** Duplicate-header renames are detected from the raw first line
  and reported, rather than letting pandas rename to `a.1` silently.
  *Reasoning:* the "never silent" rule applies to header renames too.

- **Decision:** `RunContext` carries input SHA-256, package versions,
  parameters and a timestamped decision log; `AnalysisResult` carries
  PASS/WARN/FAIL verdicts and a "what this result does not tell you" note; both
  are written into run.json and shown in report.html.
  *Reasoning:* these are exactly the audit-trail and honesty surfaces the
  project promises (reproducibility + don't over-read).

- **Decision:** `.xls`, `.ods` and `.sav` are read via optional libraries
  (xlrd, odfpy, pyreadstat) with a clear "install X" error when absent, rather
  than core dependencies.
  *Reasoning:* keeps the default install light on Colab; the formats remain
  supported for students who bring them.

## Phase 3 — Report engine decisions (2026-10-24)

- **Decision:** report.html is rendered by Jinja2 from a shipped template
  (`report/templates/report.html.j2`, package data) instead of hand-rolled
  f-strings.
  *Reasoning:* a real template keeps logic out of the markup, auto-escapes
  user-derived text, and makes the report style editable without touching
  Python.

- **Decision:** the QC verdict table shows PASS / WARN / FAIL as words first
  and colour as an accent (`verdict-*` class), not colour alone.
  *Reasoning:* students print these reports; colour alone fails in
  black-and-white and is not accessible.

- **Decision:** figures are embedded in report.html as base64 PNG data URIs;
  the template never references any external URL, stylesheet or script.
  *Reasoning:* the report must open offline on a student's machine with no
  network, and survive being emailed as one file.

- **Decision:** replay.sh / replay.ps1 no longer include `--out`, so a replay
  always writes a fresh timestamped folder.
  *Reasoning:* the old form pointed at the (now non-empty) original folder and
  was refused; a replay should reproduce numbers, never collide or overwrite.

- **Decision:** `--docx` is an opt-in extra; python-docx is not a core
  dependency (clean skip + install hint when absent).
  *Reasoning:* keeps the default install light for Colab while giving thesis
  writers the Word file they asked for.

- **Decision:** golden tests freeze only the data-card / overview CSVs (the
  environment-stable outputs), not the whole HTML (which embeds the
  environment-dependent versions + timestamps).
  *Reasoning:* a byte-locked HTML would break on every Python/pandas bump for
  no signal; section/content assertions + offline-sweep cover the HTML instead.

- **Decision:** the methods paragraph fills the named test, alpha, outcome,
  inputs, library versions, seed and Python from the run context, with a
  plain "missing values were not imputed/deleted other than the analysis's own
  documented handling" note.
  *Reasoning:* that is exactly what a thesis methods section must state, and
  it keeps the reproducibility promise visible in prose.

- **Decision:** input candidate columns are sorted so confirmed-role matches
  come first, keyed `(role != expected, name)`.
  *Reasoning:* the first listing (and default pick) should be the column the
  user already told us is their outcome/group — an earlier `reverse=False`
  sort on a boolean `matches` flag pushed non-matching columns ahead, which is
  the opposite of what a student expects.

- **Decision:** all google.colab interaction lives in
  src/auphoria/adapters/colab.py, with lazy imports and a ColabRequired
  error for laptop users.
  *Reasoning:* the notebook must stay a thin, beginner-readable front end
  with zero analysis logic and zero Colab plumbing (architecture invariant);
  a helper module also gives a single place to change upload/zip/download
  and lets the automated nbclient test stub just google.colab.

- **Decision:** analysis fit ("does it fit this data") is decided by
  auphoria.core.fitting.analyses_that_fit(), shared by the CLI menu and the
  notebook dropdown.
  *Reasoning:* two fit-checkers would drift (e.g. one forgets a required
  input); one source of truth means the notebook can never offer an
  analysis the CLI would refuse for fit reasons.

- **Decision:** the engine honors AUPHORIA_RESULTS_ROOT env var for the
  default results root.
  *Reasoning:* the nbclient kernel is a separate process so in-process test
  monkeypatching of DEFAULT_RESULTS_ROOT cannot contain its runs; an env
  override also helps users on shared machines who want results elsewhere.

- **Decision:** new analyses are built one per folder under
  src/auphoria/analyses/<id>/ with manifest + analysis + README + tests and
  maturity experimental, and the batch built 5 (ttest-paired,
  spearman-correlation, chi-square, anova-oneway, mann-whitney).
  *Reasoning:* the P1 catalogue list is the roadmap; these are the next five
  unbuilt ids (summary/describe/ttest/correlation already existed).

- **Decision:** Tukey HSD post-hoc implemented directly with
  scipy.stats.studentized_range rather than pulling in statsmodels for the
  one function.
  *Reasoning:* dependency policy keeps the install light; scipy's
  studentized-range distribution is exactly the Tukey reference and gives
  identical p-values (verified vs statsmodels values in tests).

- **Decision:** `auphoria demo --analysis <id>` gained a per-analysis demo
  map + two new sample datasets (training, diets); plain `auphoria demo`
  still runs ttest.
  *Reasoning:* the acceptance criterion 'demo works for each analysis'
  needs suitable data (paired columns, 3+ groups, two categoricals) that
  plant_growth/survey do not provide; deterministic generators keep tests
  reproducible.

- **Decision:** root conftest.py closes matplotlib figures after every test.
  *Reasoning:* analyses return open figures and per-analysis tests call
  run() directly (bypassing the engine's plt.close), which accumulated 20+
  open figures across the suite; closing per test removes the warning with no
  behavior change.
