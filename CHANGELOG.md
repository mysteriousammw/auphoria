# Changelog

All notable changes to AUPHORIA are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.0.0/); versioning follows
[Semantic Versioning](https://semver.org/).

## [0.1.0] - 2026-10-29

First release. A beginner-friendly, offline data-analysis tool for university
students who cannot code: spreadsheet/CSV in → advised analysis → plain-English
reproducible report. Built and verified across twelve phases. Everything below
is what 0.1.0 ships.

### Phase 12 — release preparation

- **Version pinned to 0.1.0** (`core/version.py`).
- **Module template + `auphoria new-module` command** (`cli/scaffold.py`,
  `cli/templates/analysis/`): scaffolds a manifest, code stub, README and
  tests for a new analysis, registers it in the catalogue, and the skeleton is
  ruff-clean, passes its own tests, and is discoverable by the registry.
  Shipped in the wheel via package-data. `tests/test_new_module_phase12.py`.
- **Release workflow** (`.github/workflows/release.yml`): tag-triggered
  `v*`; verifies (tests, ruff, validation + analysis-docs `--check`, docs
  build), builds sdist+wheel, and drafts a GitHub Release with CHANGELOG
  notes and artifacts attached. `--version` and `auphoria doctor` smoke.
- **PR template** (`.github/PULL_REQUEST_TEMPLATE.md`) and a **general bug
  template** (`.github/ISSUE_TEMPLATE/bug_report.md`), alongside the existing
  wrong-result template.
- **Pilot checklist** (`docs/pilot/pilot-checklist.md`) for 3–5 students to
  run the tool from the README alone, with a per-row "what went wrong" form
  and a ship gate; plus a short standalone feedback form.
- **CONTRIBUTING.md** gained **Maintainers** and **Succession** sections.
- **CITATION.cff** completed except for personal details (placeholders left).
- **docs/PUBLISH_CHECKLIST.md** re-checked and corrected against what was
  actually built (see below).

### Phase 11 — docs site & demo script

- **MkDocs Material documentation site** in `docs_site/` (home, 15-minute
  quickstart for macOS/Windows/Linux+WSL/Colab/uv, "which analysis do I
  choose?", per-analysis pages, gallery, troubleshooting, FAQ, responsible
  use, validation, discipline packs, decision guide, known issues).
- **Per-analysis pages** generated by `scripts/gen_analysis_docs.py` (19
  pages, regenerated, checked in).
- **Demo-video scripts**: `scripts/demo_video_script.md` (timed narration +
  shot list) and `scripts/demo_video.py` (runs the demo steps end-to-end).
- **`scripts/build_docs.sh`** — builds the site and fails on any
  WARNING/ERROR (encodes the acceptance criterion).
- **`tests/test_docs_phase11.py`** (5 tests) — docs build without warnings,
  required pages exist, analysis docs current, install blocks use
  https://github.com/mysteriousammw/auphoria + TODO-VERIFY, demo scripts exist.
- New `docs` extra (`mkdocs`, `mkdocs-material`, `mkdocs-include-markdown`);
  mkdocs deps added to `dev`.

### Phase 10 — validation

- **Maturity framework** (`docs/validation/levels.md`): `experimental` /
  `tested` (settable by the build agent) and `reviewed` / `validated` (require
  a named human reviewer in the manifest).
- **Reviewer + reference gate** (`core/manifest.py`): `maturity` is now a
  validated enum; a manifest claiming `reviewed` or `validated` without both a
  `reviewer` and a `reference` is rejected at load time and by the dashboard
  generator (`check_maturity` / `validate_maturity`, wired into the registry).
- **New manifest fields**: `reviewer`, `reference`, `known_issues`.
- **Reference fixtures** (`docs/validation/references.yaml`) for all 19
  analyses: independent-reference source, how-produced, and exact expected
  values with tolerances (from each analysis's known-answer tests).
- **Validation dashboard** (`docs/validation/dashboard.md`) generated by
  `scripts/gen_validation_dashboard.py`; the `auphoria validation` CLI command
  regenerates it and `--check` confirms it is current.
- **Known issues** (`docs/validation/KNOWN_ISSUES.md`) and a wrong-result
  **issue template** (`.github/ISSUE_TEMPLATE/wrong_result.md`).
- **`tests/test_validation_phase10.py`** (11 tests): the reviewer gate, the
  maturity enum, dashboard determinism, and per-analysis reference coverage.

### Phase 9 — discipline packs

- **Discipline packs** as optional `pyproject` extras so the core install stays
  light: `agri-animal`, `life-science`, `health`, `social`, `econ-eng`. Heavy
  dependencies (statsmodels, scikit-learn, and for life-science PyDESeq2 +
  gseapy) live inside each pack's extra.
- **`src/auphoria/packs/`** (`packs.yaml` + loader): the canonical pack
  registry (id, name, description, heavy deps) ships in the wheel.
- **Deps-guard**: before running an analysis, the engine refuses if a manifest
  `requires` module is missing, printing the exact pack install command
  (`pip install "auphoria[<pack>] @ git+https://github.com/mysteriousammw/auphoria"`) instead of a
  raw ImportError.
- **Manifest `pack` (list) + `requires` fields**, validated by pydantic, added
  to the 10 advanced analyses.
- **`auphoria packs`** command (list packs + install commands + dep status)
  and **`auphoria list --pack <name>`** filter; `auphoria doctor` reports pack
  dependency status.
- **`docs/DISCIPLINE_PACKS.md`** and a README "Optional discipline packs"
  section with exact https://github.com/mysteriousammw/auphoria install syntax.
- **`tests/test_packs_phase9.py`** covering the registry, deps-guard
  messaging, and the CLI commands.

### Phase 8 — advanced analyses

- **Ten advanced analyses** (P1/P2), each with manifest + analysis + README +
  tests and an explicit "needs expert review" notice when used outside
  intended conditions: `ancova` (ANCOVA), `mixed-effects` (linear mixed
  model), `pca`, `factor-analysis` (EFA), `clustering-kmeans`,
  `kaplan-meier` (survival), `cox-regression`, `diagnostic-test`
  (ROC/sensitivity/specificity), `ml-classification-eval`,
  `ml-regression-eval`.
- **`expert_review` notice mechanism** (new): `AnalysisResult.expert_review`
  + `add_expert_review()`; threaded through the engine (run.json) and rendered
  as a prominent banner in report.html.
- **6 new sample datasets** (`growth_cov`, `schools`, `psych`, `survival`,
  `diagnosis`, `features`) with deterministic generators for demos/tests.
- Advisor `rules.yaml` entries and demo-map entries for all 10 new analyses.
- Registry now skips `__pycache__` when discovering analyses.

### Phase 7 — advisor

- **Question-driven advisor** (`src/auphoria/advisor/`): for a data +
  research question, recommends the built analyses that fit (each with a
  one-line reason) and rules out the rest (with the specific refusal). The
  decision logic lives in `rules.yaml` (a readable encoding of
  `docs/research/decision-guide.md`) and is evaluated by `advisor_engine.py`.
- **7 research questions** (describe / compare / relate / predict /
  over_time / reliability / reduce) + catch-all rules; every built analysis is
  covered by at least one rule.
- **Wizard advice step**: after column kinds/roles are confirmed, the wizard
  asks "What do you want to know?" and shows ranked advice + ruled-out before
  the analysis menu.
- **`auphoria suggest`** upgraded from a hard-coded stub to the advisor
  (`--question/-q <id>` narrows to one question).
- **42 advisor scenario tests**; `src/auphoria/advisor` added to pytest
  `testpaths` (the suite was previously skipped silently).

### Phase 6 — core analyses batch 1

- **Five new P1 analyses** (all `maturity: experimental`), each with
  manifest.yaml, analysis.py, README.md and scipy-verified tests:
  `ttest-paired`, `spearman-correlation`, `chi-square`, `anova-oneway` (with
  Tukey HSD post-hoc and Levene/Shapiro warnings), `mann-whitney`.
- `auphoria demo --analysis <id>` for all 9 built analyses, with two new
  deterministic sample datasets (`training`, `diets`).
- 39 new per-analysis tests (hand-computed answers vs scipy references plus
  bad-input cases); root `conftest.py` closes matplotlib figures after tests.

### Phase 2 + 3 — core engine & report engine

- **Core engine (Phase 2):** rich data loading (csv/tsv/txt/xlsx/xls/ods/
  json/dta/sav with delimiter sniffing, flagged encoding fallback,
  duplicate-header detection, multi-sheet Excel, quoted paths, blank-row
  detection), a "data card" profiler, column-role suggestions, pydantic
  manifest validation, structured decision log, and a `describe` analysis.
- **Report engine (Phase 3):** `report.html` rendered with **Jinja2** from a
  shipped template — summary cards, QC verdict table, result tables,
  base64-embedded figures, full decision log, methods paragraph, "what this
  result does not tell you" box, and software versions. Self-contained with
  zero external resource requests (opens offline).
- **Optional Word output:** `auphoria run --docx`.
- **Methods paragraph generator** (library versions, test name, alpha, inputs,
  seed, Python version).
- `auphoria run --kind COL=KIND`; replay scripts write to a fresh timestamped
  folder.
- Deps: `jinja2` in core; optional extras `excel`, `docx`, `dev`. Output-folder
  overwrite rule enforced and tested.

### Phase 1 — foundation & core engine

- Repository scaffold: `pyproject.toml`, MIT license, setuptools packaging,
  console script `auphoria`.
- Core engine (`src/auphoria/core`): errors with plain-English messages,
  logging to `log.txt`, SHA-256 input hashing, parameter/input validation, and
  the analysis registry (loads every analysis from its `manifest.yaml`).
- Single entry point `auphoria.run(...)` used by the CLI and the IBM-free
  Colab notebook. No analysis logic lives in the front ends.
- CLI (`auphoria`) with a beginner default interface and an expert flag:
  `auphoria` (interactive guided flow), `auphoria run`, `auphoria list`,
  `auphoria info`, `auphoria sample`, `auphoria versions`.
- Data adapters: CSV/TSV/TXT and Excel (`auphoria[excel]`); advisor profiles
  columns and reports missingness.
- Report writer: `report.html`, `methods.txt`, results CSVs, PNG figures,
  `run.json`, `replay.sh`, `replay.ps1`, `log.txt`.
- Reproducibility: package versions, seed, resolved parameters, input
  SHA-256, replay command.
- First three analyses (`summary`, `ttest`, `correlation`) with manifests,
  modules, READMEs, and hand-checked tests.
- Sample data (`auphoria.sample_data`): plant-growth experiment and survey.
- `scripts/set_repo_url.py`; Colab notebook; CI workflow; decision log and
  publication checklist.

### Known limitations (0.1.0)

- All 19 analyses ship at `maturity: experimental` — none has yet been
  promoted to `tested`/`reviewed`, since promotion decorates the manifest
  after real (un-piloted) use.
- Legacy Excel `.xls` is not supported; users are told to convert.
- `_load_sample_for(name)` in `cli/main.py` returns the first sample
  regardless of `name` (affects only the example-command column picker).
- Offline install still needs one internet step (pip); docs cover Colab as the
  no-install path.
